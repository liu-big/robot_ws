## CAN ID 设置

- 参数 `CAN_ID`（0x2009），可用上位机或通信类型 7 修改
- 主机 ID 参数 `CAN_MASTER`（0x200a），官方 ROS 例程使用 **0xFF**
- 超时保护 `CAN_TIMEOUT`（0x200b）：为 0 时不启用；非 0 时长时间无 CAN 指令会停机

## 29-bit 扩展帧 ID 结构

手册与官方 ROS 例程使用同一编码：

```
can_id = (通信类型 << 24) | (主机ID << 8) | 电机ID
```

| 字段 | 位域 | 说明 |
|------|------|------|
| 通信类型 | Bit28~24 | 0=查ID, 1=运控, 2=反馈, 3=使能, 4=停止 … |
| 主机 ID | Bit15~8 | 本机 CAN_MASTER，ROS 例程用 **0xFF** |
| 电机 ID | Bit7~0 | 目标电机 CAN_ID |

**常见错误**: 把主机 ID 和电机 ID 颠倒，例如写成 `0x000001FF`（错）而不是 `0x0000FF01`（对）。

### 示例（主机 0xFF）

| 操作 | 扩展帧 ID | cansend |
|------|-----------|---------|
| 查询电机 0x7F | `0x0000FF7F` | `cansend can0 0000FF7F#0000000000000000` |
| 使能电机 0x7F | `0x0300FF7F` | `cansend can0 0300FF7F#0000000000000000` |
| 查询电机 0x01 | `0x0000FF01` | `cansend can0 0000FF01#0000000000000000` |

`cansend` 用 **8 位十六进制** 表示扩展帧；`##` 是 CAN-FD 语法，不是扩展帧标志。

### 实测（本机第四条腿）

- 出厂默认 CAN_ID 常为 **0x7F**，不一定为 0x01。
- 查询 `0x0000FF7F` 有应答 `0x00007FFE`。
- 同一总线上两台电机 **CAN_ID 不能相同**，需用上位机把其中一台改为 0x01、另一台 0x02。

## 通信类型

| 类型 | 功能 |
|------|------|
| 0 | 获取设备 ID |
| 1 | 运控模式控制（角度/角速度/力矩/Kp/Kd） |
| 2 | 电机反馈数据 |
| 3 | 使能运行 |
| 4 | 停止运行 |
| 6 | 设置机械零位 |
| 7 | 设置电机 CAN_ID |
| 17 | 单个参数读取 |
| 18 | 单个参数写入（掉电丢失） |
| 21 | 故障反馈 |
| 22 | 参数保存 |

## 安全注意（手册）

- **运行中不可切换控制方式**，需先发送停止命令
- 使用前检查接线，避免短路
- 不要超过峰值扭矩使用

## Linux 测试

```bash
~/robot_ws/scripts/can-hub-up.sh

# 监听灵足反馈（扩展帧）
candump -tz -e can0

# ROS2 官方例程（默认关节 ID 0x01）
~/robot_ws/scripts/run-leg1-dual.sh
```

改测抬腿电机: 编辑 `src/robstride_ros_sample/src/main.cpp` 中 `0x01` → `0x02`，重新 `colcon build`。

## 与 C620 的区别

| | can0 灵足 RS03 | can1 大疆 C620 |
|--|----------------|----------------|
| 帧格式 | **扩展 29-bit** | **标准 11-bit** |
| 波特率 | 1 Mbps | 1 Mbps |
| 控制方式 | RobStride 协议 | 0x200 电流包 |

两路 CAN **必须分开**，不能混在同一 SocketCAN 接口。
